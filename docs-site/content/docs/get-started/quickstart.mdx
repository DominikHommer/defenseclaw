This guide takes you from nothing to a blocked tool call in about five minutes. It uses Claude Code. For another agent, replace `claudecode` with its connector name: `codex`, `copilot`, `cursor`, `devin`, `antigravity`, `kiro`, `opencode`, `amp` or `hermes`. The [support matrix](/docs/support-matrix) shows which agents can block on your OS.

The block comes from a one-rule test pack that matches only `echo defenseclaw-demo-marker`. Agents refuse the destructive commands the default rules target, so a harmless marker is the reliable way to see a block.

## Block a tool call in seven steps

<Steps>

<Step>

### Install

<include>../../snippets/install-commands.mdx</include>

On a first install the installer asks which agent to guard: type `claudecode` (or its number). It ends with the next command, `defenseclaw init --connector claudecode`. Requirements and the other install options are on [Install](/docs/get-started/install).

</Step>

<Step>

### Run `defenseclaw init`

```bash
defenseclaw init --connector claudecode
```

Press Enter through the prompts. `init` sets up Claude Code in **observe** mode: DefenseClaw logs what the agent does and blocks nothing yet. At **Select connector(s) for action enforcement**, leave the box unchecked. Plain `defenseclaw init` sets up every agent it finds. `init` ends by starting the gateway and printing a report like this. The sample was captured with `--skip-gateway`, so its Sidecar row says not started; yours says started:

<include>../../snippets/first-run-report.mdx</include>

`✓` is done and `-` is optional or skipped. You need no LLM key and no Cisco AI Defense key for this guide. If the report says `partial`, it names what needs attention, for example an agent that is not installed; `defenseclaw doctor` explains the rest. Every option is in the [init and quickstart reference](/docs/reference/first-run).

</Step>

<Step>

### Check that it is watching

Open Claude Code and ask it something that uses a tool, such as "list the files in this directory". If Claude Code was already running, quit and reopen it first so it loads the new hooks. Then look at what DefenseClaw recorded:

```bash
defenseclaw status    # the guarded agents, their modes and recent activity
defenseclaw tui       # the live dashboard: alerts, audit and logs
```

New events show up within a second or two. If nothing does, run `defenseclaw doctor`.

</Step>

<Step>

### Turn on blocking for Claude Code

```bash
defenseclaw guardrail mode action --connector claudecode
```

This switches only Claude Code to **action** mode, which enforces the rules. Other agents stay in observe. The running gateway applies the mode without a restart.

In action mode, hooks use the global hook fail mode, which is `closed` on a new install: Claude Code's tools are blocked while the gateway is down. To allow and log those calls instead, run `defenseclaw guardrail fail-mode open`. Running `defenseclaw quickstart` again without `--mode` keeps the mode and fail mode each agent already has.

</Step>

<Step>

### Add the demo rule

Copy the default rule pack, add one CRITICAL rule that matches only `defenseclaw-demo-marker`, and point Claude Code at the copy:

{/* regression-check: the PowerShell tab below is pending a native Windows run. */}

<Tabs items={['macOS / Linux', 'Windows (PowerShell)']}>

<Tab value="macOS / Linux">

```bash
PACK=~/.defenseclaw/policies/guardrail/first-guardrail
cp -R ~/.defenseclaw/policies/guardrail/default "$PACK"
cat > "$PACK/rules/first-guardrail.yaml" <<'EOF'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
EOF
defenseclaw guardrail validate-pack "$PACK"
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

<Tab value="Windows (PowerShell)">

```powershell
$Pack = "$HOME\.defenseclaw\policies\guardrail\first-guardrail"
Copy-Item -Recurse "$HOME\.defenseclaw\policies\guardrail\default" $Pack
Set-Content -Path "$Pack\rules\first-guardrail.yaml" -Encoding ascii -Value @'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
'@
defenseclaw guardrail validate-pack $Pack
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

</Tabs>

The copy keeps every default rule. `use-pack` validates the pack, pins its digest in `guardrail.custom_packs.first-guardrail` and switches Claude Code to it. The gateway loads the pack on its next reload; nothing restarts.

</Step>

<Step>

### Ask the agent to run the marker

In Claude Code, ask:

> Please run `echo defenseclaw-demo-marker`.

The command does not run. Claude Code tells you DefenseClaw blocked it:

> DefenseClaw policy blocked this action (rule DEMO-MARKER-BLOCK: First-guardrail demo marker). Do not retry it in another form.

In another terminal, list the latest alerts:

```bash
defenseclaw alerts --limit 5
```

The block is the newest row: severity `CRITICAL`, action `scan-finding`, target `PreToolUse`. `defenseclaw alerts --show 1` prints the whole record:

```text
Alert #1
  Severity:  CRITICAL
  Action:    scan-finding
  Target:    claudecode:PreToolUse
  Decision:  blocked
  Connector: claudecode
  Rule:      DEMO-MARKER-BLOCK: First-guardrail demo marker
  Scanner:   hook-rules
```

The same alert is in the **Alerts** panel of `defenseclaw tui` (press `2`):

![The Alerts panel of defenseclaw tui showing one CRITICAL scan-finding alert for claudecode:PreToolUse with rule DEMO-MARKER-BLOCK](/images/get-started/tui-alerts-demo-block.png)

</Step>

<Step>

### Undo the demo

```bash
defenseclaw guardrail use-pack --clear --connector claudecode   # back to the default pack
defenseclaw guardrail mode --clear --connector claudecode       # back to observe
```

Then delete the `first-guardrail` folder under `~/.defenseclaw/policies/guardrail/`. Keep Claude Code in action mode instead if you want it to enforce the default rules from now on.

</Step>

</Steps>

## If it did not block

- The agent was open before `init`: quit and reopen it.
- `defenseclaw doctor` shows a failing hook or gateway row: see [Troubleshooting](/docs/troubleshooting).
- The agent is still in observe mode: run `defenseclaw guardrail status`.
