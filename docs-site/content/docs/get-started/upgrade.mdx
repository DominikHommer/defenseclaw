`defenseclaw upgrade` installs the latest release and keeps your configuration, audit data, device key and agent setup. 1.0.4 supports upgrades from 1.0.3, 1.0.2 and 0.8.10. For 0.8.x, see [Upgrade from 0.8.x](/docs/appendix/upgrade-from-0-8).

## Upgrade

```bash
defenseclaw upgrade
```

The command downloads the latest release's installer (`install.sh` on macOS and Linux, `install.ps1` on Windows), checks it against that release's `checksums.txt` and runs it. The installer:

1. Downloads the release and checks every file. With `cosign` 2.0 or later installed, it also verifies the Sigstore signature and stops if that fails.
2. Builds the new version next to the running one and checks that it starts and that your configuration can be migrated.
3. Stops the gateway, keeps the current install in `~/.defenseclaw/previous`, swaps in the new version and runs `defenseclaw migrate`.
4. Starts the gateway and waits for it to report healthy.

If a step fails, the installer puts the previous version back, restarts it and keeps the failed attempt in `~/.defenseclaw/.failed-<time>`. Every run writes a log to `~/.defenseclaw/logs/`. On Windows the installer continues in a new PowerShell window so the running command can release its files.

| Command | What it does |
| --- | --- |
| `defenseclaw upgrade` | Upgrade to the latest release. Asks before changing anything. |
| `defenseclaw upgrade --yes` | The same, without prompting. |
| `defenseclaw upgrade --version X.Y.Z` | Install a specific release, newer or older. |
| `defenseclaw rollback` | Put back the install that the last upgrade replaced. Run it again to roll forward. |
| `defenseclaw migrate --check` | List pending config migrations. Exit 0: can be applied. 1: cannot. 2: the config is from a newer release. |

If the `defenseclaw` command does not start, run the install command again. It repairs any install and keeps your data:

## Rollback

```bash
defenseclaw rollback
```

Rollback swaps the live install with the one the last upgrade replaced: programs, Python environment, configuration and data as they were at upgrade time. Anything written since moves into `~/.defenseclaw/previous` and returns when you roll forward. One previous install is kept, and rollback needs no network.

- Each install shows only its own audit events. Read the other install's with `~/.defenseclaw/previous/bin/defenseclaw-gateway audit export --db ~/.defenseclaw/previous/data/audit.db`.
- Rollback starts the restored gateway and waits up to 3 minutes. If it does not come up, rollback exits `1` and agent hooks are not guarded until `defenseclaw-gateway start` succeeds.
- If an upgrade or rollback is interrupted, run the same command again. The installer first restores the install it was replacing.
- Rolling back to 0.8.x, and the Windows 0.8.7-0.8.10 Setup case, are covered in [Upgrade from 0.8.x](/docs/appendix/upgrade-from-0-8#roll-back-to-08x).

## Update notices

When a newer release exists, interactive commands and the TUI show one line: `DefenseClaw X.Y.Z is available (you have A.B.C) — run 'defenseclaw upgrade'`. The check runs at most once a day and never in scripts, JSON output or CI. Nothing is installed unless you run `defenseclaw upgrade`.

## Update settings

| Key | Default | What it does |
| --- | --- | --- |
| `update.check` | `true` | Show the update notice. Also off with `DEFENSECLAW_NO_UPDATE_CHECK=1`. |
| `update.channel` | `stable` | The release channel. `stable` is the only one. |
| `update.source` | `https://github.com/cisco-ai-defense/defenseclaw` | Where release files come from. Set an `https://` base URL for a mirror. |

```bash
defenseclaw config set update.check false
```

On Windows the `DisableSelfUpdate` enterprise policy also turns the notice off. A managed device does not self-update; the [lifecycle](/docs/enterprise/operate/lifecycle) applies updates.

### Install from a mirror

```bash
defenseclaw config set update.source https://mirror.example.com/defenseclaw
```

The mirror must serve the paths GitHub serves: `releases/latest` (a redirect to the newest tag) and `releases/download/<tag>/` with the installer, the release files, `checksums.txt` and `checksums.txt.bundle`.

`update.source` changes only where files come from. The certificate identity that signed the official releases is built into DefenseClaw, so a mirror must serve the official signed `checksums.txt` and its bundle, and the machine needs `cosign` 2.0 or later. Without it, the upgrade stops before it runs anything. `DEFENSECLAW_REPO` is the deprecated alias; `update.source` wins when both are set. A first install has no `config.yaml`, so use `DEFENSECLAW_REPO` for the installer there ([Installer](/docs/reference/commands/installer#mirror)).

## Renamed and removed connectors

This applies if you used Windsurf, Gemini CLI, OpenHands or OmniGent before 1.0.4.

- **Windsurf is now Devin.** The upgrade moves your `windsurf` settings to the [`devin` connector](/docs/connectors/devin) and replaces the old hooks. You do nothing.
- **Gemini CLI was removed.** Use [Antigravity](/docs/connectors/antigravity). Remove DefenseClaw's hooks from Gemini CLI's settings once.
- **OpenHands and OmniGent were removed.** The `config_version` 9 migration drops their entries from `config.yaml` and records them in `migration-v9.json`, and the upgrade cleans up the hook files and managed files DefenseClaw wrote for them. Set up another agent with `defenseclaw setup <connector>` if one of them was your only connector.

<Accordion title="Windsurf is now Devin: what the upgrade changes" id="windsurf-is-now-devin">

Windsurf was renamed Devin Desktop (Cognition). The [`devin` connector](/docs/connectors/devin) covers Devin CLI and Devin Desktop's default Devin Local agent; both read the same hook config. The move runs during `defenseclaw upgrade`, on the next `defenseclaw-gateway restart`, or when you run `defenseclaw setup devin`:

- In `~/.defenseclaw/config.yaml`, `guardrail.connector`, `claw.mode` and every per-connector `windsurf` block become `devin`, keeping their settings. If a `devin` block already exists, it wins and the `windsurf` block is dropped; the upgrade output names the dropped key. Connector name lists, `asset_policy` rule connectors and observability route selectors are renamed the same way.
- The gateway removes only the hook entries DefenseClaw wrote into `~/.codeium/windsurf/hooks.json`. Hooks from other tools stay.
- It deletes `~/.defenseclaw/hooks/windsurf-hook.sh` (and `windsurf-hook.ps1`) and `~/.defenseclaw/connector_backups/windsurf/`.
- It installs the Devin hooks in `~/.config/devin/config.json` (Windows: `%APPDATA%\devin\config.json`).

Devin Desktop builds before 3.9.19 still run the legacy Cascade agent without DefenseClaw hooks. To confirm, run `defenseclaw doctor`, check that the Devin hook row passes, then open a new Devin tab or session.

</Accordion>

<Accordion title="Gemini CLI was removed: cleanup steps" id="gemini-cli-was-removed">

If another connector is configured, the upgrade removes `geminicli` from `guardrail.connectors` and moves `guardrail.connector` and `claw.mode` to the first remaining connector. If Gemini CLI was your only connector, the upgrade stops before it changes anything; `defenseclaw migrate --check` names the connector. On its next start, the gateway deletes `~/.defenseclaw/hooks/geminicli-hook.sh` (and `.ps1`) and the connector's OTLP token. It never edits `~/.gemini`.

Do this once, before you set up Antigravity:

1. If Gemini CLI was your only connector, remove it on the release you still have. This refuses to remove the last connector without `--force`; DefenseClaw then enforces nothing until step 5.

   ```bash
   defenseclaw setup remove geminicli --yes --force
   ```

2. Open `~/.gemini/settings.json` (or `$GEMINI_CLI_HOME/.gemini/settings.json`; on Windows `%USERPROFILE%\.gemini\settings.json`). Under `hooks`, delete every group whose `hooks` list contains `"name": "defenseclaw"`, then delete any event key left empty.
3. If `telemetry.otlpEndpoint` in the same file contains `/otlp/geminicli/`, delete the `telemetry` object or restore your own values.
4. Do not touch `~/.gemini/config/`. That directory belongs to Antigravity.
5. Restart the gateway and set up Antigravity:

   ```bash
   defenseclaw-gateway restart
   defenseclaw setup antigravity
   ```

<Callout type="warn" title="Gemini CLI can be blocked until the gateway restarts">
Until the gateway restarts after `geminicli` leaves `config.yaml`, the old hook script still calls a gateway endpoint that no longer exists. With `guardrail.hook_fail_mode: closed`, the default for new installs, that blocks every Gemini CLI action.
</Callout>

If `config.yaml` still names `geminicli`, the gateway refuses to start and its error points here; step 1 fixes it.

</Accordion>
