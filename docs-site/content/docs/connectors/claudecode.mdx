DefenseClaw adds hooks to Claude Code's settings and receives its native OpenTelemetry logs and metrics. This is a hook connector: Claude Code talks to Anthropic directly and no proxy is involved.

## Platform support

<ConnectorSupport id="claudecode" />

## Set up

```bash
defenseclaw setup claude-code                # observe (default): record only
defenseclaw setup claude-code --mode action  # block on policy hits
```

On Windows, run the same commands in PowerShell. Quit and reopen Claude Code afterwards so it loads the hooks.

## What it can block or ask

<HookEventsList connector="claudecode" />

- In action mode `PreToolUse` can deny a tool call or ask you first. The question appears inside Claude Code.
- The prompt, permission, task, stop, compaction, config and elicitation events can also block.
- Events that carry a tool's result (`PostToolUse`, `PostToolUseFailure`, `PermissionDenied`) are advisory. DefenseClaw scans them and records findings, but the tool has already run.
- Observe mode never blocks. It records what action mode would have blocked.

## Files it changes

| What | macOS and Linux | Windows |
| --- | --- | --- |
| Hooks and OpenTelemetry settings | `~/.claude/settings.json` | `%CLAUDE_CONFIG_DIR%\settings.json` (default `%USERPROFILE%\.claude`) |
| Hook program | `~/.defenseclaw/hooks/claude-code-hook.sh` | `%USERPROFILE%\.local\bin\defenseclaw-hook.exe` (one-line install) or `%LOCALAPPDATA%\DefenseClaw\HookRuntime\defenseclaw-hook.exe` (Setup installer) |
| Connector credentials | `~/.defenseclaw/hooks` | `%USERPROFILE%\.defenseclaw\hooks` |

DefenseClaw backs up `settings.json` first. Teardown restores the backup, or removes only its own entries if you edited the file since.

## Limits

- `disableAllHooks: true` in any Claude Code settings file turns every hook off. The gateway raises a guardrail-degraded alert, `defenseclaw status` shows DEGRADED, and `defenseclaw doctor` fails the **Claude Code hooks** row. Remove the key and restart Claude Code.
- A project's `.claude/settings.json`, or a file passed with `claude --settings`, can do the same for its sessions. DefenseClaw cannot see a `--settings` file.
- Commands you type in Claude Code's own bash mode are your input, not an agent action. They are not checked.
- Keep the gateway running while Claude Code runs. Claude Code's telemetry goes to this account's gateway port, so give each account on a shared computer its own port.
- Per-user hooks live in a file you own. The [enterprise standalone profile](/docs/enterprise/machine-policy) puts them in machine policy instead.

## On a managed computer

The per-user commands on this page do not run on a computer with a standalone enterprise install. There `defenseclaw` offers only `sandbox` commands: anything else prints "This computer is managed; only `defenseclaw sandbox` commands are available here." and exits 2. On native Windows the managed `defenseclaw` refuses `setup claudecode` and `setup remove`, and has no `guardrail` group.

The administrator manages Claude Code in the managed `config.yaml`. `guardrail.connectors.claudecode: {}` adds it, the connector's `mode` and `hook_fail_mode` tune it, and `guardrail.connectors.claudecode.enabled: false` removes it. Apply the change as in [Change the config](/docs/enterprise/lifecycle#change-the-config), then check it with `enterprise policy verify` ([Machine policy](/docs/enterprise/machine-policy#inspect-export-and-verify)).

## Turn it off

These commands are for a per-user install.

```bash
defenseclaw guardrail disable --connector claudecode --yes
```

This keeps Claude Code's settings. Turn it back on with `defenseclaw guardrail enable --connector claudecode`. To remove the connector, run `defenseclaw setup remove claudecode --yes` (add `--force` if it is the last one). With a single connector, `defenseclaw guardrail disable --yes` turns the whole guardrail off.
