DefenseClaw writes hooks, an OpenTelemetry exporter and a notify bridge into Codex's `config.toml`. This is a hook connector: Codex talks to OpenAI directly and no proxy is involved.

## Platform support

<ConnectorSupport id="codex" />

## Set up

```bash
defenseclaw setup codex                # observe (default): record only
defenseclaw setup codex --mode action  # block on policy hits
```

On Windows, run the same commands in PowerShell. Quit and reopen Codex afterwards.

## What it can block or ask

<HookEventsList connector="codex" />

- In action mode `PreToolUse` and `PermissionRequest` can deny a call before the tool runs.
- `UserPromptSubmit`, `PostToolUse`, `Stop` and (on newer Codex versions) the session, subagent and compaction events can also block. Each answers in its own way: `PostToolUse` cannot undo the finished tool, and `Stop` blocks by continuing the turn.
- Codex has no native ask. A confirm verdict becomes an alert with the original action kept. You can review it in audit or the TUI, but not resume the call.
- Codex loads skills without a hook of their own. DefenseClaw refuses a denied skill when you select it as `$name` or when a tool call reads its folder.

## Files it changes

| What | macOS and Linux | Windows |
| --- | --- | --- |
| Hooks, OpenTelemetry, notify | `$CODEX_HOME/config.toml` (default `~/.codex`) | `%CODEX_HOME%\config.toml` |
| Hook program | `~/.defenseclaw/hooks/codex-hook.sh` | `%LOCALAPPDATA%\DefenseClaw\HookRuntime\defenseclaw-hook.exe` |
| Connector credentials | `~/.defenseclaw/hooks` | `%USERPROFILE%\.defenseclaw\hooks` |
| Proxy bypass for telemetry | `$CODEX_HOME/.env` (marked block, only when a proxy is set) | not written |

Everything outside DefenseClaw's marked fields is kept. Teardown restores the backup, or removes only DefenseClaw's entries.

## Limits

- `codex features disable hooks` keeps the entries but runs none of them. DefenseClaw raises a guardrail-degraded alert, `defenseclaw status` shows DEGRADED and `defenseclaw doctor` fails the **Codex hooks** row. Run `codex features enable hooks`.
- Delete only DefenseClaw's `command` lines from `config.toml` and Codex will not start. Use `defenseclaw setup codex --yes` or `defenseclaw doctor --fix` to repair it.
- Hosted tools, file reads and `write_stdin` have no complete hook coverage.
- After you rotate a model key, or after an upgrade, run `codex app-server daemon restart`. The daemon keeps the environment and telemetry credential it started with.
- Each gateway start on Windows runs Codex's app-server once to read its requirements. That process contacts OpenAI.

## Turn it off

```bash
defenseclaw guardrail disable --connector codex --yes
```

This keeps Codex's settings. Turn it back on with `defenseclaw guardrail enable --connector codex`. To remove the connector, run `defenseclaw setup remove codex --yes` (add `--force` if it is the last one).
