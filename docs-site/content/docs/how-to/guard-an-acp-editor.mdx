This page puts Kiro behind the [ACP guard](/docs/features/acp-guard) in Zed, then finds agents the guard does not cover.

## Before you start

- DefenseClaw is [installed](/docs/get-started/install) and the gateway runs.
- You use Zed or JetBrains, and the agent runs from a terminal once already (for Kiro, run `kiro-cli login`). An editor starts the agent with no terminal, so a first-run question would leave the thread on a spinner.

## Guard Kiro in Zed

1. Start the gateway and add a guarded entry.

   ```bash
   defenseclaw-gateway start
   defenseclaw acp setup --client zed --agent kiro
   ```

   {/* needs-live-capture: output of acp setup */}

   Setup writes one `DefenseClaw · Kiro` entry, a private token file and a contract lock. It keeps your other Zed settings and agent servers, but it rewrites the file as plain JSON: the comment block before the opening `{` stays, and other comments and trailing commas are dropped. A failed write rolls all three changes back. For JetBrains use `--client jetbrains`.

2. Check the binding.

   ```bash
   defenseclaw acp status
   ```

   A healthy binding shows the guard on and the profile and mode it uses. Setup starts in observe mode.

3. Open a Kiro thread from the `DefenseClaw · Kiro` entry in Zed, then look at the events in the TUI Audit panel or with `defenseclaw audit export`.

4. When the events look right, turn on blocking.

   ```bash
   defenseclaw acp setup --client zed --agent kiro --activate
   ```

## Find agents that are not guarded

An editor may launch an agent directly. Those launches skip the guard.

```bash
defenseclaw acp detect
```

```text
  zed - ~/.config/zed/settings.json
  guarded    DefenseClaw · Kiro
  !   UNGUARDED  cursor -> launched from the client's own registry; replace with a guarded cursor entry
  foreign    Something Else (left untouched)
```

| Label | Meaning |
| --- | --- |
| `guarded` | The entry starts `defenseclaw-acp`. |
| `UNGUARDED` (direct launch) | A native agent the guard can wrap. |
| `UNGUARDED` (client registry) | The editor resolves and starts the agent itself, so there is nothing to wrap. |
| `foreign` | Not an agent DefenseClaw knows. It is never changed. |

Wrap the direct launches:

```bash
defenseclaw setup acp
```

This runs the same setup for each pair and points your existing entry at the guard, keeping its key and `env`. It starts in observe mode; add `--activate` for action mode. A client-registry entry cannot be wrapped: remove it in the editor after the guarded entry exists, or the agent can still start without the guard.

## Guard several agents in one editor

Run setup once for each agent. Each run writes its own entry and contract lock and leaves the others alone.

```bash
defenseclaw acp setup --client zed --agent kiro --profile locked --activate
defenseclaw acp setup --client zed --agent devin --profile watch
```

Each editor and agent pair has its own profile, so Kiro can enforce while Devin only observes. Without `--profile`, both use the `default` profile, and setup refuses to change that profile's mode for one pair only. Profile keys are in the [reference](/docs/reference/acp-guard#configuration).

## Check it worked

```bash
defenseclaw acp status
```

```text
ACP guard: off (1 binding)
  Bindings:
    zed/kiro             NEEDS ATTENTION  profile default (observe, inherited)
      ! contract lock is missing or unsafe
  Fix with: defenseclaw acp verify, then re-run defenseclaw acp setup for that pair
```

The sample shows a binding whose contract lock is missing, so it needs attention. After a good setup the binding is not flagged. `defenseclaw doctor` lists the same bindings and fails on a broken one.

## Undo

```bash
defenseclaw acp remove --client zed --agent kiro
```

This removes the entry and the contract lock for that pair.
