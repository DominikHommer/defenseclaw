Use the generator to build the exact `defenseclaw setup guardrail --non-interactive` command for CI or scripts. Pick the agent, mode, scanner, judge and approval options. The command rewrites itself, and a notes panel warns about combinations that will not behave as you expect, such as human approval in observe mode.

Nothing here runs on your machine. Choose **Bash / zsh** for macOS and Linux or **PowerShell** for native Windows, then copy the result into that host's terminal.

## What it covers

- The agent picker, with native ask, fail-closed and Windows support shown for each.
- Mode, scanner backend (`local`, `remote`, `both`), detection strategy and rule pack.
- The judge: model, provider, Bedrock, Vertex AI and Azure settings, TLS options. Only the selected provider's flags are written.
- Human approval and its minimum severity (turned off in observe mode).
- `--port`, `--block-message`, `--workspace`, `--restart` and `--disable`.

`--disable` collapses the command to `defenseclaw setup guardrail --disable`, which is global. For one agent use `defenseclaw guardrail disable --connector <id>`.

The two choices with no flag are the hook fail mode (use `defenseclaw guardrail fail-mode`) and judge fallback models (`guardrail.judge.fallbacks` in `config.yaml`). Every flag is in the [`setup guardrail` reference](/docs/reference/guardrail-setup).
