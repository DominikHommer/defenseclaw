# Fixed synthetic contained-hook build inputs

This opt-in Linux/amd64 contributor harness has been compiled and its first
contained run failed before payload startup. It installs no runtime catalog or production factory.
It exercises the actual FileStore binding, shared ingress policy evaluator and
owned hook producer. It calls the producer directly: Manager.Create, LaunchGate
and a common ExecutionPolicy receipt are outside this canary. The test adapter
creates no policy receipt.

The fixed fixture lists all twelve current connector schemas. Version strings
select the existing parser contracts; the executable is a synthetic Go payload,
not any vendor agent. The payload calls the existing hook client with literal
JSON requests. The destructive-looking block command is JSON data and is never
executed. OmniGent exercises only its raw Go transport; its Python policy bridge
is not run. Fail-open and silence/registration behavior remains unqualified for
every vendor, including Copilot and Hermes.

The first native selector is
`TestContainedNativeHookClaudeUsesActualSharedEvaluator`; a separately sequenced
`TestContainedNativeHookAllTwelveUseActualSharedEvaluator` uses the same payload.
Both require the distinct reviewed 361 peer and unchanged static Bubblewrap,
the generated payload digest, exact held objects, a private hook producer and
owned native cleanup. The native test records the actual shared observer
decision, full binding, fixed helper output and native terminal. It checks allow
and block, a 200 ms silent interval and in-memory endpoint admission loss.
Admission loss is not a simulated removed socket or a vendor tool veto. A
missing decision is not proof that a silent connector is safe. No network or
seccomp grant changes are made here.

The build workflow is manual. Its own-path push registers it with the entire
job skipped; a separately authorized manual dispatch builds exactly one artifact.
It runs four closed safe host selectors: fixture JSON validation, a payload
exchange test using an injected fake client, and all twelve formats through the
actual existing gateway evaluator using an in-process host transport, and a
fake cleanup-uncertainty/retention test. None of
those selectors clones, starts the native peer or invokes the produced payload.
The two native selectors are compiled but never selected by this recipe.

The helper checks reviewed source hashes and a clean exact Git checkout, verifies
baseline pins from raw `git cat-file blob HEAD:<path>` bytes rather than Windows
working-copy line endings, checks
the pinned module checksums, builds the CGO-disabled payload, replaces only the closed
Go pin template with that payload digest, and compiles the tagged gateway test
CGO-disabled driver with `go test -c`. Safe host tests use the race detector;
the driver is compiled without running those tests. No runtime hash, argv, endpoint or environment override
can select an admitted payload. Both images, original and generated pin source,
local compiler-input hashes, exact test logs, module/build metadata and a bounded
manifest are retained together for ROOT, author and independent inert review.
`go version -m` reads metadata; neither image, `ldd`, an installer nor a contained
payload is executed. A failed build retains its available logs. Artifact and
source review must finish before a separate concrete native recipe is considered.

The first build-only run, 39212296154 at 1d2f72a8, failed in the safe host
oracle before its connector subtests. The default registry has fourteen built-ins:
the twelve fixed agent-hook cases plus OpenClaw and ZeptoClaw. Fixture and fake
payload tests passed, and the synthetic payload was built; the driver was not
compiled or run. The corrected oracle requires exactly those two additional
built-ins and refuses any other registry name. It does not add a vendor case or
change a hook decision.

The second build-only run, 39267098717 at 50c6be77, reached all twelve
host oracle schemas: eleven passed, while Claude failed the fixture's incorrect
exit-2 expectation for its structured PreToolUse denial. The existing producer
and client express that denial as exit 0 with `hookSpecificOutput`, the exact
`PreToolUse` event, `permissionDecision: deny` and a nonempty reason. The fixed
oracle now checks that complete shape in both the host oracle and compiled
native assertions; it rejects exit 0 alone, allow-shaped output, malformed or
ambiguous JSON and the exit-2 fallback in the evaluated block phase. Allow
requires empty streams and exit 0. A separately checked sealed endpoint returns
HTTP 503, which the strict native client maps to exit 2, empty stdout and its
fixed HTTP-503 fail-closed stderr line. The host oracle exercises that same
closed-admission handler without a listener or child and requires no additional
policy decision. The actual native admission-loss row uses the same assertion.
These checks preserve all twelve schemas, actual evaluator binding/action
checks, and the cleanup contract. The failed run made no native attempt.

Source-only local checks may run the pure Python tests, formatting/actionlint and
`build_only.py --dry-check <canonical-repo> <TASK-draft-root>`. The two dry-check
paths only choose text to compare with fixed source hashes; this mode performs no
build, dependency acquisition, source mutation or native operation.

The held listener directory is readonly to the guest; this is a trusted-host
boundary, not protection against a malicious same-UID host replacing names.
An early registered cleanup owner retains every allocated source file, image
and directory. It releases these only after native/endpoint completion; any
uncertain close stays sticky and retains the exact remaining references until
the test process exits. The all-twelve matrix stops on its first failed subcase,
and cleanup uncertainty refuses new case ownership in that process.
The native case creates its host FileStore in separately held private
`gateway/sandboxes` directories under the retained fixture root. It has no
automatic recursive cleanup. Before a producer exists, the same owner durably
revokes the exact minted binding before releasing any pin; an ambiguous failed
Mint without a usable ID retains the store and reports incomplete cleanup.
Once a producer exists, its seal, native-stop, revoke and drain order applies.
The host store is neither a guest mount nor public fixture evidence. Synchronous
store/filesystem I/O is not made hard-deadline-interruptible by the context.
Failures preserve fixture residue and uncertain native custody. Successful
cleanup requires actual native wait, endpoint drain and binding revocation
before exclusive assets are released. Production qualification remains false.
